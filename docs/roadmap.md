# HongGuoRust 产品路线图（M0–M14）

更新：2026-11-21

## 1. 项目定位与边界

HongGuoRust 是面向 Windows 10/11 x64 的开源桌面媒体客户端。React/Tauri 2 负责界面与 IPC，Rust 单独管理 libmpv 会话，后续以可扩展的内容服务提供目录、检索、选集和合法媒体播放链接。

**产品目标**：从用户已选本地媒体或已获授权的内容源出发，形成“浏览 → 搜索 → 详情/选集 → 播放/下一集 → 观看历史/断点续播 → 收藏”的完整闭环。优先复用现有框架，不自研媒体解码器。

**内容与授权边界**：项目不隶属于任何短剧平台，不绕过鉴权、DRM、付费墙或服务条款。外部 Provider 只对接有明确使用权限且允许客户端调用的接口和媒体。公开演示资源必须具有允许使用的许可。没有外部合法源时，仍交付完整的本地媒体体验。

**发布边界**：M5 Windows NSIS 的本机验证不等同于允许公开分发。公开二进制发布由 [Issue #7](https://github.com/Zhaokangbo/HongGuoRust/issues/7) 跟踪第三方 LGPL/GPL/FFmpeg 条款、可再链接/对应源码、依赖来源及干净 Windows 10/11 测试。此事项从现在起并行推进，M13 前必须关闭阻断项。

## 3. 近期计划：M8

### M8-A：检索、排序和手动列表（[PR #12](https://github.com/Zhaokangbo/HongGuoRust/pull/12)）

- “我的视频 / 最近播放 / 我的收藏”支持标题和文件名检索。
- 支持最新添加、标题自然排序、最近播放和观看进度排序。
- 从当前筛选结果播放时，生成仅驻留内存的有序列表；播放器提供上一部、下一部手动切换。
- 不修改已有 libmpv 解码逻辑、历史/收藏存储，也不执行自动播放下一部。
- **状态**：Windows M1/M2 CI 已通过，负责人 Windows 8/8 实机验收全部通过；[PR #12](https://github.com/Zhaokangbo/HongGuoRust/pull/12) 已于 2026-11-21 合入 `main`（`b8155d2`）。

验收：准备至少三部本地 MP4；验证检索/排序、显示计数、结果顺序、列表首尾禁用、单独打开本地文件/HTTPS 清除列表、错误时不错误推进队列。

### M8-B：自动连播和列表策略（[PR #14](https://github.com/Zhaokangbo/HongGuoRust/pull/14)，已完成）

- 只在用户**明确开启自动连播**后，在真实自然 EOF 触发下一部；手动 Stop、报错、关闭窗口不得触发。
- 新一集加载失败时给出可理解的错误与重试选项，不做无限循环；可设置关闭/单次列表播放/顺序播放等策略，初版避免无限循环。
- 队列与播放会话绑定，防止旧 EOF、异步回调误操作新会话。
- 验收覆盖自然 EOF、用户 Stop、窗口关闭、缓冲错误、已移走的视频、列表末尾与快速切换。
- **状态**：Windows M1/M2 与负责人 Windows 9/9 项实机验收全部通过，PR #14 于 2026-11-21 合并至 `main`（`4f5e653`）。

## 4. 核心产品升级：M9–M10

### M9：Provider/ContentService 可扩展架构

**M9-A：统一内容源注册表及本地媒体适配（已完成）**
- 新增 Provider ID 命名空间：`demo:forest-demo` / `local:<media-id>`；兼容旧的未带命名空间演示 ID。
- 统一返回内容源能力、分页搜索、详情、单集播放目标；同一客户端支持 LocalDemoProvider 与用户已导入 MP4 的 LocalLibraryProvider。
- 只通过已有本地媒体库读取、播放本机文件；不扫描磁盘、不上传文件，也不依赖第三方内容 API。
- 新增内容源选择和全部来源浏览；Rust 单元测试覆盖命名空间碰撞、分页边界、非法 URL、无效 ID 和旧行为兼容。
- **M9-A 验收结果**：Windows M1/M2 CI 全绿，Windows 9/9 项实机验收通过；[PR #15](https://github.com/Zhaokangbo/HongGuoRust/pull/15) 已于 2026-11-21 合入 `main`（`886ba5b`）。

**M9-B1（已完成）：Provider 请求超时、取消、错误恢复**
- Rust 请求注册表：同一时刻最多 32 项活动请求，单次超时 50 ms～30 s；请求 ID、超时与并发重复校验；自动清理完成/取消的请求。
- 支持 `catalog_cancel_request`；超时/取消会在 Provider 边界和支持请求上下文的 Provider 实现中检查。
- 前端为搜索/分页/详情请求添加 8 秒等待上限、AbortSignal 取消、过期响应忽略、错误说明和重试入口。
- 使用受控慢 Provider 的 Rust 测试验证取消、截止时间、重复请求和清理；不将模拟故障 Provider 暴露为真实内容源。
- **限制**：通用请求取消是协作式机制，不能强制终止阻塞的系统调用。真正的 HTTP Provider 仍必须实现连接/读取超时及取消检查。
- **状态**：[PR #16](https://github.com/Zhaokangbo/HongGuoRust/pull/16) 的 Windows M1/M2 CI 及负责人 8/8 项 Windows 实机验收全部通过，2026-11-21 合入 `main`（`d00a681`）。

**M9-B2（开发中）：用户自有 JSON 媒体清单 Provider**
- 为用户明确选择的 `schemaVersion: 1` JSON 清单提供单独的 `manifest` Provider；存储在本机 `LOCALAPPDATA\\HongGuoRust\\owned-manifest.json`，不扫描、复制或上传任何媒体文件。
- 导入时检查文件大小、结构版本、ID 唯一性、文本和集数上限，以及每一集是否为现有播放器支持的直接公开 HTTPS MP4。
- 支持“自有媒体清单”搜索、详情、选集、播放、重启后恢复及一键清空（双重确认）；检索返回的是元数据，不包含 URL。
- 输入仅作为用户自选的公开直链清单，无法证明内容权利，也不提供 DRM、网站登录或绕过第三方鉴权。
- **M9-B2 验收门槛**：Windows M1/M2 全绿；验证有效/无效 JSON 导入、同 ID 的不同来源隔离、HTTPS 播放、重新打开后恢复、清空不删除原始文件及 M7/M8/M9-B1 回归。

**后续可选 M9-B3：在明确获得 API 与媒体授权后再接入受控远端服务**
- 另行设计传输级连接/读取超时、可取消 HTTP 请求、授权证明、来源域名策略及重定向验证。


- 统一 Provider 搜索、内容详情、剧集列表、播放链接解析和能力声明；Provider 不直接控制 libmpv。
- 明确超时、取消、分页、错误码、内容 ID 命名空间和权限边界。
- 适配现有本地源和演示源，配备**有明确授权**的非演示内容源，或在缺少合法接口时提供可验证的本地/用户配置源适配器。
- 对 Provider 输入、媒体链接和缓存进行边界校验；不提供 DRM 绕过、盗链、未授权抓取。
- 验收：不同 Provider 在相同 UI 合约下完成检索/详情/选集/播放，失败时可恢复、不同来源 ID 不冲突。

### M10：产品级短剧闭环

- 首页/分类/专题、站内检索、详情与选集页、更新状态、最近播放与收藏联动。
- 清晰展示剧集排序、已看集数、下一集动作与缺失/不可用提示；允许从上次剧集继续。
- 设计空结果、加载、取消、失败和无播放权限等页面状态。
- 验收：在合法可用资源上独立完成“发现 → 选集 → 观看 → 下一集 → 退出 → 续播”，且本地内容模式同样可用。
- **M10 视为首个完整产品体验里程碑**，不代表已经满足公共发行条件。

## 5. 播放体验与工程质量：M11–M12

### M11：播放器高级体验

- 缩略图预览：使用异步生成与限量缓存，移动鼠标时不频繁让主播放会话 Seek；支持任务取消和异常/无索引退化。
- 常用快捷键及冲突处理；字幕轨、音轨选择；保留用户设置。
- 高 DPI、不同窗口大小、全屏切换、控制栏可访问性、输入焦点状态。
- 验收：预览不会明显阻塞播放/音频，切换轨道与恢复播放状态一致，核心交互可通过键盘执行。

### M12：稳定性、性能、安全

- 模拟断网、慢速下载、短时抖动、损坏文件、无音轨、异常退出、文件被移动。
- Windows 真机资源观察：CPU、内存、句柄、线程、音画同步、长时间播放与退出延迟；先测基线，再设量化阈值。
- 回归 CI + 真机验收：状态机、媒体生命周期、队列竞态、缓存限额、JSON 断电安全与敏感日志最小化。
- 验收：有可复现的性能与可靠性报告，满足事先确定的发布基线。**M12 是技术稳定性里程碑**。

## 6. 发布与长期能力：M13–M14

### M13：发布体系与合规

- 先完成 Issue #7：第三方许可证审核、所需版权声明/许可文本/对应源码与可再链接条件、FFmpeg/mpv 构建配置和来源说明。
- 干净 Windows 10/11 x64 安装、卸载、应用数据保留、升级与回滚的测试；不假设本地开发机器环境。
- 版本号、变更日志、可复现依赖锁定、发布包哈希、签名、GitHub Release 流程；自动更新只在安全与回滚方案成熟后启用。
- **M13 是正式交付门槛**。没有通过法律与技术发布条件，不生成或公开发布安装包。

### M14：按需求选择扩展

- 稳定的 Provider 插件扩展契约、可选的其他桌面平台、用户授权的跨设备同步或更多媒体索引能力。
- 仅在前置接口与安全/发布基线稳定、存在明确用户价值后立项；不作为 M10 产品闭环的阻断项。

## 7. 工程交付节奏

1. 每个小阶段从最新已合并 `main` 创建独立分支与 Draft PR；不要并行改变同一播放器状态机。
2. 先提交可审计的功能边界、文档、测试；Windows M1/M2 只认该提交最终结果。
3. 能使用 M2 Debug EXE 就不重复完整 NSIS 打包；调试 EXE 配套自有应用目录中的运行时 DLL。
4. CI 全绿后由 Windows 真机测试新增 UI、媒体及生命周期边界；保留测试步骤与问题证据。
5. 双重验收通过后再 squash 合入 `main` 并更新本路线图状态。
6. 第三方内容合法来源与公共分发合规是独立门槛，不因演示源或本机验证成功而自动放行。

**M8-A/M8-B、M9-A/M9-B1 已验收合并 → M9-B2 自有媒体清单 → M10 产品闭环 → M11 播放体验 → M12 稳定性 → M13 合规发布 → M14 可选扩展**。
