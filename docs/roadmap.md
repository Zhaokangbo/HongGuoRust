# HongGuoRust 产品路线图（M0–M14）

更新：2026-11-22

## 1. 项目定位与边界

HongGuoRust 是面向 Windows 10/11 x64 的开源桌面媒体客户端。React/Tauri 2 负责界面与 IPC，Rust 单独管理 libmpv 会话，后续以可扩展的内容服务提供目录、检索、选集和合法媒体播放链接。

**产品目标**：从用户已选本地媒体或已获授权的内容源出发，形成“浏览 → 搜索 → 详情/选集 → 播放/下一集 → 观看历史/断点续播 → 收藏”的完整闭环。优先复用现有框架，不自研媒体解码器。

**内容与授权边界**：项目不隶属于任何短剧平台，不绕过鉴权、DRM、付费墙或服务条款。外部 Provider 只对接有明确使用权限且允许客户端调用的接口和媒体。公开演示资源必须具有允许使用的许可。没有外部合法源时，仍交付完整的本地媒体体验。

**发布边界**：M5 Windows NSIS 的本机验证不等同于允许公开分发。公开二进制发布由 [Issue #7](https://github.com/Zhaokangbo/HongGuoRust/issues/7) 跟踪第三方 LGPL/GPL/FFmpeg 条款、可再链接/对应源码、依赖来源及干净 Windows 10/11 测试。此事项从现在起并行推进，M13 前必须关闭阻断项。

## 3. 近期计划：M8

### M8-A：检索、排序和手动列表（[PR #12](https://github.com/Zhaokangbo/HongGuoRust/pull/12)）

- “我的视频 / 最近播放 / 我的收藏”支持标题和文件名检索。
- 支持最新添加、标题自然排序、最近播放和观看进度排序。
- 从当前筛选结果播放时，生成仅驻留内存的有序列表；播放器提供上一部、下一部手动切换。
- 不修改已有 libmpv 解码逻辑、历史/收藏存储，也不执行自动播放下一部。
- **状态**：Windows M1/M2 CI 已通过，负责人 Windows 8/8 实机验收全部通过；[PR #12](https://github.com/Zhaokangbo/HongGuoRust/pull/12) 已于 2026-11-21 合入 `main`（`b8155d2`）。

验收：准备至少三部本地 MP4；验证检索/排序、显示计数、结果顺序、列表首尾禁用、单独打开本地文件/HTTPS 清除列表、错误时不错误推进队列。

### M8-B：自动连播和列表策略（[PR #14](https://github.com/Zhaokangbo/HongGuoRust/pull/14)，已完成）

- 只在用户**明确开启自动连播**后，在真实自然 EOF 触发下一部；手动 Stop、报错、关闭窗口不得触发。
- 新一集加载失败时给出可理解的错误与重试选项，不做无限循环；可设置关闭/单次列表播放/顺序播放等策略，初版避免无限循环。
- 队列与播放会话绑定，防止旧 EOF、异步回调误操作新会话。
- 验收覆盖自然 EOF、用户 Stop、窗口关闭、缓冲错误、已移走的视频、列表末尾与快速切换。
- **状态**：Windows M1/M2 与负责人 Windows 9/9 项实机验收全部通过，PR #14 于 2026-11-21 合并至 `main`（`4f5e653`）。

## 4. 核心产品升级：M9–M10

### M9：Provider/ContentService 可扩展架构

**M9-A：统一内容源注册表及本地媒体适配（已完成）**
- 新增 Provider ID 命名空间：`demo:forest-demo` / `local:<media-id>`；兼容旧的未带命名空间演示 ID。
- 统一返回内容源能力、分页搜索、详情、单集播放目标；同一客户端支持 LocalDemoProvider 与用户已导入 MP4 的 LocalLibraryProvider。
- 只通过已有本地媒体库读取、播放本机文件；不扫描磁盘、不上传文件，也不依赖第三方内容 API。
- 新增内容源选择和全部来源浏览；Rust 单元测试覆盖命名空间碰撞、分页边界、非法 URL、无效 ID 和旧行为兼容。
- **M9-A 验收结果**：Windows M1/M2 CI 全绿，Windows 9/9 项实机验收通过；[PR #15](https://github.com/Zhaokangbo/HongGuoRust/pull/15) 已于 2026-11-21 合入 `main`（`886ba5b`）。

**M9-B1（已完成）：Provider 请求超时、取消、错误恢复**
- Rust 请求注册表：同一时刻最多 32 项活动请求，单次超时 50 ms～30 s；请求 ID、超时与并发重复校验；自动清理完成/取消的请求。
- 支持 `catalog_cancel_request`；超时/取消会在 Provider 边界和支持请求上下文的 Provider 实现中检查。
- 前端为搜索/分页/详情请求添加 8 秒等待上限、AbortSignal 取消、过期响应忽略、错误说明和重试入口。
- 使用受控慢 Provider 的 Rust 测试验证取消、截止时间、重复请求和清理；不将模拟故障 Provider 暴露为真实内容源。
- **限制**：通用请求取消是协作式机制，不能强制终止阻塞的系统调用。真正的 HTTP Provider 仍必须实现连接/读取超时及取消检查。
- **状态**：[PR #16](https://github.com/Zhaokangbo/HongGuoRust/pull/16) 的 Windows M1/M2 CI 及负责人 8/8 项 Windows 实机验收全部通过，2026-11-21 合入 `main`（`d00a681`）。

**M9-B2（已完成）：用户自有 JSON 媒体清单 Provider**
- 为用户明确选择的 `schemaVersion: 1` JSON 清单提供单独的 `manifest` Provider；存储在本机 `LOCALAPPDATA\\HongGuoRust\\owned-manifest.json`，不扫描、复制或上传任何媒体文件。
- 导入时检查文件大小、结构版本、ID 唯一性、文本和集数上限，以及每一集是否为现有播放器支持的直接公开 HTTPS MP4。
- 支持“自有媒体清单”搜索、详情、选集、播放、重启后恢复及一键清空（双重确认）；检索返回的是元数据，不包含 URL。
- 输入仅作为用户自选的公开直链清单，无法证明内容权利，也不提供 DRM、网站登录或绕过第三方鉴权。
- **M9-B2 验收结果**：[PR #17](https://github.com/Zhaokangbo/HongGuoRust/pull/17) Windows M1/M2 和 Windows 9/9 项实机验收全部通过，2026-11-21 合入 `main`（`8790ff8`）。

**后续可选 M9-B3：在明确获得 API 与媒体授权后再接入受控远端服务**
- 另行设计传输级连接/读取超时、可取消 HTTP 请求、授权证明、来源域名策略及重定向验证。


- 统一 Provider 搜索、内容详情、剧集列表、播放链接解析和能力声明；Provider 不直接控制 libmpv。
- 明确超时、取消、分页、错误码、内容 ID 命名空间和权限边界。
- 适配现有本地源和演示源，配备**有明确授权**的非演示内容源，或在缺少合法接口时提供可验证的本地/用户配置源适配器。
- 对 Provider 输入、媒体链接和缓存进行边界校验；不提供 DRM 绕过、盗链、未授权抓取。
- 验收：不同 Provider 在相同 UI 合约下完成检索/详情/选集/播放，失败时可恢复、不同来源 ID 不冲突。

### M10：产品级短剧闭环

**M10-A（已完成）：首页与真实分类发现**
- 内容剧库默认打开“首页”，统一展示已注册 demo/local/manifest Provider 实际返回的元数据。
- 支持按内容来源、已加载条目的真实 `genre` 分类、关键词搜索、加载更多/刷新、焦点卡片和列表卡片进入现有详情/选集。
- 焦点卡片优先选择用户自有清单或本地媒体，其次演示内容；**不是**基于真实观看数据的热度排名，不标榜推荐算法或未经授权的作品。
- 以每页最多 50 条分页加载；分类仅在已加载条目中筛选，未加载完时不声称完整分类/总榜。
- 不修改原有“演示内容”检索与 Provider 选择、“我的视频”“最近播放”“我的收藏”以及 M7/M8 播放状态机；增加纯分类与焦点选取的 Node 自动化测试。
- **M10-A 验收结果**：Windows M1/M2 CI 同一提交全绿，负责人 11/11 项 Windows 实机验收通过；[PR #18](https://github.com/Zhaokangbo/HongGuoRust/pull/18) 已于 2026-11-21 合入 `main`（`96e15b8`）。

**M10-B（开发中）：剧集详情、选集与显式切换**
- 统一详情按后端提供的集数排序，并在播放器底部显示选中作品、当前集数和总集数。
- 提供“上一集 / 下一集”按钮，严格限制在当前 Provider 作品真实选集边界；单集本地 MP4 两个按钮均禁用。
- 自然 EOF 只显示“本集播放完毕，点击下一集继续”的提示；最后一集提示全集结束；**不自动跳下一集**。
- 使用 Rust 原生 session ID 校验 Ended/Error 状态，仅当前剧集的结束/失败事件有效，避免旧会话错误提示。
- 切换成功才更新当前剧集；缺失或失效的选集返回错误，保留既有导航上下文，不无限重试、不自动跳过。
- 单独打开本地 MP4/HTTPS、手动停止、从 M8 我的视频在线播放时均清空之前的 Provider 剧集上下文。
- 不修改 M8 原有本地临时队列自动连播，也不记录新的跨会话剧集历史；后者留给 M10-C。
- **M10-B 验收门槛**：Windows M1/M2 CI 通过最终提交，Rust/Node 测试覆盖导航边界、乱序集数与原生会话 EOF；Windows 实机验证多集演示/自有 JSON、单集本地媒体、切换异常、M7–M10-A 回归。

**M10-C1（开发中）：Provider 观看历史与跨重启续播**
- demo/manifest 真实选集的观看历史存于独立 `provider-progress.json`；原生 Session 校验后持久化并恢复，详情页显示继续观看入口。
- local Provider 延用 M7 本地历史；M8 本地队列和 M10-B 手动剧集导航不变，媒体源变化时旧断点无效。
- 通过 Windows M1/M2 + [M10-C1 真机验收](acceptance/m10-c1.md) 后才可合并。

**M10-C2（开发中）：首页继续观看、已看集数与最近播放联动**
- 首页新增真实的「继续观看」模块，汇总 Provider 和本地视频播放进度并按时间排序；剧集历史在 Rust 验证当前媒体源后才对外展示。
- 「最近播放」同时展示 Provider 与 M7 本地历史，保留本地历史清除、收藏、排序；作品详情标记已看剧集数、每集进度及完播后手动下一集。
- 不自动跳集、不暴露清单 URL、删除/替换清单不能用旧断点误播放；遵守 [M10-C2 验收](acceptance/m10-c2.md)。
- 依赖 M10-C1：当前开发分支从 C1 验证提交派生，先完成 C1 验收并合并，再调整 C2 PR 的最终基线与 CI。
- 首先审查现有 M7 只记录本地媒体的历史结构；如扩展到有权使用的 HTTPS 清单，需建立 Provider 作用域历史 ID 并处理来源内容失效及退出恢复。

- 首页/分类/专题、站内检索、详情与选集页、更新状态、最近播放与收藏联动。
- 清晰展示剧集排序、已看集数、下一集动作与缺失/不可用提示；允许从上次剧集继续。
- 设计空结果、加载、取消、失败和无播放权限等页面状态。
- 验收：在合法可用资源上独立完成“发现 → 选集 → 观看 → 下一集 → 退出 → 续播”，且本地内容模式同样可用。
- **M10 视为首个完整产品体验里程碑**，不代表已经满足公共发行条件。

## 5. 播放体验与工程质量：M11–M12

### M11：播放器高级体验

**M11-A（开发中）：播放器键盘快捷键及帮助**
- 增加与现有 Rust IPC 对接的 Space/K、方向键/J/L、M、F/F11、Esc、? 播放快捷键；以输入焦点和播放状态为边界，避免误触发。
- 键盘事件解析为纯 TypeScript 并加入 Node 自动测试；全屏和音量界面联动，帮助浮层可随时关闭。
- 只有在 [M11-A 验收](acceptance/m11-a.md) 的同一最终提交 Windows M1/M2 + Windows 真机全绿且先决 #20/#21 合并后，才可标记完成。

**M11-B（开发中）：独立预览任务与进度条缩略图**
- 进度条悬停 280ms 去抖、5 秒分桶，将时间与当前 session ID 发送给 Rust；图片浮层留在 HTML 控制区内，避免被 Win32 原生 HWND 遮挡。
- 独立 libmpv image VO 抽取缩略图，不调用主播放句柄 Seek，JPEG 临时输出自动清理，有界 LRU 缓存（12 张/约 2MiB），旧会话/旧请求必须丢弃。
- 本地 MP4 优先验收，HTTPS 直接 MP4 弱网、无索引时只显示时间并安全退化；最终效果需 [M11-B Windows 真机验证](acceptance/m11-b.md) 后才认定完成。
- 上游 M11-A Windows 实机 10/10 已通过，PR #20/#21/#22 仍需按各自验收与合并要求处理。

- M11-B Windows 12/12 已通过，PR #23 暂未合并；接下来继续 M11-C1。

**M11-C1（开发中）：内嵌音轨 / 字幕轨选择**
- Rust 主 libmpv worker 枚举实际 track-list，仅返回受限的 ID、语言、标题、选中状态，不向前端暴露媒体 URL/本地路径。
- UI 的音轨/字幕选择器仅对当前 native session 生效；音轨仅接受存在的轨道 ID，字幕可明确关闭；切换前后状态和旧请求隔离。
- 增加可复现本地双音轨+内嵌字幕 MP4 生成脚本；详见 [M11-C1 验收](acceptance/m11-c1.md)。
- 本阶段不做用户偏好持久化、外部字幕文件扫描/自动加载或字幕样式编辑；这些内容留待 M11-C2。
- 保持 Draft 直至最终提交 M1/M2 + Windows 真机 12/12 全部通过，且先决 #20–#23 按顺序完成验收/合并。

- **M11-C1 实机验收：用户已明确反馈 12/12 全部通过**；对应 PR #24 仍 Draft，合并依赖前置 #20–#23 的验收与授权。

**M11-C2（开发中）：播放器偏好设置持久化**
- Rust 新增版本化 `player-settings.json` 本地设置文件，原子保存音量、上次非静音音量、倍速与本地自动连播开关，不触碰 M7/M10 的观看历史/收藏文件。
- 每个新 libmpv 会话在 loadfile 前应用保存的音量、倍速；切集和重启不再重置为 100%/1×，原生确认后才持久保存修改。
- 自动连播偏好只作用于 M8 本地临时播放列表，不改变 Provider 手动切集语义；损坏或版本不兼容的设置文件不会被静默覆盖。
- 新增 Rust/Node 测试，按 [M11-C2 Windows 真机验收](acceptance/m11-c2.md) 完成后再考虑合并，依赖 #20–#24 顺序验收/合并。






- 缩略图预览：使用异步生成与限量缓存，移动鼠标时不频繁让主播放会话 Seek；支持任务取消和异常/无索引退化。
- 常用快捷键及冲突处理；字幕轨、音轨选择；保留用户设置。
- 高 DPI、不同窗口大小、全屏切换、控制栏可访问性、输入焦点状态。
- 验收：预览不会明显阻塞播放/音频，切换轨道与恢复播放状态一致，核心交互可通过键盘执行。

### M12：稳定性、性能、安全

**M12-A（开发中）：播放会话诊断与 Windows 资源基线**

- 在 Rust player worker 中记录内存态的会话打开/加载/启动信号/自然完播/异常/Stop 计数，缓冲次数及累计时长，以及 libmpv 释放次数、最近/最大释放耗时。
