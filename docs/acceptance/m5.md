## Scope

Package the Rust/Tauri app and pinned libmpv-2.dll into a per-user NSIS setup for Windows 10/11 x64. The M5 configuration is an additive override: it preserves existing M1–M4 non-bundle builds.

- src-tauri/tauri.bundle.conf.json enables NSIS only and declares a verified libmpv runtime as bundled resource.
- src-tauri/windows/hooks.nsh copies the runtime from $INSTDIR\resources\libmpv-2.dll beside the installed hongguorust.exe, where Windows can load it.
- scripts/build-windows.ps1 performs npm build, pinned libmpv SHA-256 check, MSVC import-library preparation, Rust tests and NSIS packaging. The staging DLL is removed in finally; never commit the DLL.
- Default current-user installation avoids admin elevation. The default WebView2 bootstrapper requires internet if WebView2 is missing.

Build in Windows PowerShell from repository root:

    .\scripts\build-windows.ps1

Expected candidate: `src-tauri/target/release/bundle/nsis/*-setup.exe`. The automated candidate build and hook behavior have been verified on the hosted Windows runner for the commit recorded above. Run the smoke against **your own newly built candidate** before manual playback testing:

```powershell
.\scripts\build-windows.ps1
$setups = @(Get-ChildItem 'src-tauri/target/release/bundle/nsis' -Filter '*-setup.exe' -File)
if ($setups.Count -ne 1) { throw "Expected exactly one installer, got $($setups.Count)" }
Get-FileHash $setups[0].FullName -Algorithm SHA256
.\scripts\smoke-installer.ps1 -Installer $setups[0].FullName
```

`smoke-installer.ps1` silently installs into a unique temporary directory, performs its checks and **uninstalls**. Do not expect its test installation to remain on the machine. The script works both on GitHub Actions (`RUNNER_TEMP`) and on an ordinary Windows PC (system temp fallback). To run **interactive playback acceptance**, start the same `*-setup.exe` normally, install it, launch HongGuoRust, and use the checks below.

## App-private Vulkan loader (after first installed-app UI failure)

The pinned libmpv binary imports `vulkan-1.dll`. Earlier debug/CI builds prepared the loader in a temporary directory on machines without a system Vulkan loader; the first installer packaged libmpv but **omitted** Vulkan. The NSIS installer therefore needed a clean-machine dependency fix, independent of whether the hosted Windows UI Automation timeout had precisely that root cause.

The M5 build now passes `-ForceBuildVulkan` to the existing pinned-source Vulkan-Loader recipe (KhronosGroup/Vulkan-Headers and Vulkan-Loader v1.4.321 commits verified by SHA). It stages an application-local `vulkan-1.dll`, records its build SHA-256, and packages the DLL beside `hongguorust.exe`. The installer smoke checks for this file before launch and after uninstall. M1/M2 workflow calls to `prepare-mpv-msvc.ps1` are unchanged because this flag is opt-in.

**Licensing gate**: Vulkan-Loader is a separate upstream dependency. Include the relevant source, license and notices for the exact pinned revisions in distribution review; this commit is still a CI test candidate, not authorization for a public binary Release. A self-built loader binary hash is recorded in the build logs rather than assumed stable across toolchain versions.

## Cloud CI artifact policy and provenance inspection

- The PR `Windows M5 NSIS candidate` workflow builds a **real** NSIS `*-setup.exe` on a GitHub-hosted Windows Server 2022 runner and uses it for real install/IPC/uninstall smoke. It currently does **not** upload a downloadable setup or bundled media DLLs.
- After a successful smoke, the workflow uploads only `m5-package-evidence` (`build-evidence/m5-package-report.json`), containing the candidate commit, installer checksum, the installed file paths/sizes/SHA-256 values and any installed license/notice file candidates. The JSON contains **no executable payload**.
- `distribution_authorized: false` in this report is intentional: the binary may be technically valid while redistribution evidence remains incomplete. A file named LICENSE/NOTICE is an inventory clue, not proof of compliance.
- The pinned upstream `zhongfly/mpv-winbuild` LGPL dev archive includes a libmpv DLL and import library, not a full machine-verifiable component license/source bundle. The upstream README warns that it cannot guarantee all LGPL-incompatible packages are disabled; the exact FFmpeg configuration and complete statically-linked component manifest need independent review. See [upstream README](https://github.com/zhongfly/mpv-winbuild/blob/main/README.md), [mpv Copyright](https://github.com/mpv-player/mpv/blob/master/Copyright) and [FFmpeg legal checklist](https://ffmpeg.org/legal.html).
- Do not mark M5 complete or upload the bundled installer until the exact corresponding source, third-party license/notice manifest and clean-machine acceptance are finished. Windows M1/M2 downloadable non-installer validation remains a separate existing workflow.

## Real Windows acceptance handoff (manual; not inferred from CI)

Record: Windows version/build, installer's SHA-256, exact Git commit, whether WebView2 and Vulkan runtime were previously installed, monitor scale (100% or 150%), and any redacted application log. Do not upload sample media with unauthorized redistribution rights.

1. From the **installed** app (not the earlier unpacked EXE), select a known local MP4: verify decoded moving video and actual audio; pause/resume, seek forward/back, change volume and speed, fullscreen/windowed, stop and reopen.
2. Play the same previously validated **public HTTPS MP4**: confirm actual moving video, audio, progress and seek. If it fails, separately check local proxy variables, DNS/HTTPS availability and the app's **sanitized** logs; don't assume a decoder regression from a generic mpv `Raw(-13)` error.
3. Close the app after playback and verify its process and child `msedgewebview2` instances from this app exit. Perform 20 open/play/stop/exit cycles, noting crashes or persistent processes. Repeat visible UI controls at 100% and 150% display scale.
4. Install on a **clean Windows 10 x64 and clean Windows 11 x64** system without dev tools or mpv. Verify installed `libmpv-2.dll` and `vulkan-1.dll` alongside the EXE, launch and play; inspect native imports and any VC-runtime dependency. Testing only a development PC is insufficient.
5. Verify WebView2-present and WebView2-absent cases, online bootstrap behavior and expected failure messaging when offline. Current `downloadBootstrapper` strategy may require internet when WebView2 is absent.
6. Upgrade an existing test installation with a **different candidate version** when available, checking saved app data and DLL replacement; then uninstall and verify shortcuts, uninstaller entry and app-private DLL cleanup without removing unrelated files.

**Pass rule**: CI PASS + both clean Windows versions PASS + real local/HTTPS playback PASS + required regression/upgrade checks PASS + distribution notices/source review PASS. Until then M5 is a tested **candidate**, and PR #6 must remain Draft.
