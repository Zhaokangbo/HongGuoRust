# M2 Windows validation

## What has been observed

The user confirmed that the M2-A executable played a local video with picture and audible sound on a real Windows desktop after deploying libmpv-2.dll. The output device model was not specified. The Windows runner separately sampled changing colors in the native child HWND and decoded 48,000 samples of the known AAC tone at 439 Hz. The runner had no WASAPI loopback endpoint.

## Default Windows desktop observations

The default x64 executable at commit 77d898f2456f594a8a543883b367694b25821905 was exercised on a physical Windows desktop at 96 DPI. The real picker opened the Unicode fixtures. H.264 frame colors, A/B replacement, stop and reopen, corrupt input, natural EOF and recovery, window resize, minimize/restore, occlusion/repaint and all 20 playing-window close cycles passed. The first cycle closed the main window with its picker open. Each process exited normally with no surviving observed descendants. A separate Idle IPC smoke found the expected UIA text after 842 ms and checked seven descendants. The output-device listening evidence above applies to M2-A. The user has now also manually tested the *default M2 executable* on Windows x64 at 150% display scaling and reported PASS for actual video playback, video resizing, minimize/restore, and controls/video-region layout; the exact `GetDpiForWindow` value was **not** measured. In the same default-executable acceptance report the user confirmed PASS for local video playback, window lifecycle, switching and error recovery, and audible output via **speakers**. Treat these as user-reported physical-desktop observations, not as CI measurements or verified GPU-present timestamps. CI checks appear in PR #3.

## Default client and tests

The Rust service is part of the default Windows build. Every open comes through the native Unicode picker. IPC returns the accepted session ID. Only libmpv's PlaybackRestart can advance Loading to Playing. A single worker owns each successive libmpv handle and drops it before loading the next file. State updates require the corresponding session ID. Closing keeps the HWND alive until the worker joins. Logs distinguish file-loaded, playback-restart, release and worker exit. The pixel test measures screen observation; the GPU presentation timestamp is unavailable.

The M1 smoke launches the release executable, reads the actual UIA text, checks the Rust IPC marker and verifies normal process-tree exit. On the original failing PR runner only the window name was found. The successful Push used the same WebView2 version. The historical failure log lacked a DOM tree, screenshot and backend IPC marker, so its exact cause cannot be reconstructed. A rejected first snapshot used to end frontend polling permanently. The default client retries IPC, and the smoke explicitly requests WebView accessibility, activates the window, waits for the WebView tree and captures failure evidence under diagnostics/.

The M2 smoke exercises the production file picker, replacement, stop, corrupt input, recovery, window geometry on available monitors, minimize/restore, occlusion and twenty launches and closes during playback. Each cycle checks the exit code and its observed descendants. Only scales actually reported by GetDpiForWindow count as real display coverage. The hosted runner's SetDPI utility may change the configured preference without changing the active desktop's window or system DPI. In that case the test reports `SKIP` for the unavailable 150% transition rather than claiming PASS; if the system DPI does change but the application window fails to follow, the test remains a FAIL. Review the CI logs and the PR for observed results. A skipped scale requires a manual 150% display-scaling check on Windows 10/11 before final M2 acceptance.

## Hosted runner post-restore framebuffer limitation

The Windows hosted GitHub Actions runner demonstrated real pixels from the H.264 fixture **before** minimize/restore, including red/blue and replacement green, and validates video HWND geometry and process lifecycle. After minimize/restore, its screen-grab samples sometimes returned unrelated desktop colors while the failure screenshot showed a correctly rendered green fixture. This is not reliable evidence of a libmpv failure. Hosted runs therefore explicitly log `SKIP` for post-restore and occluder *pixel observations*, while still checking restored HWND visibility, size, playing-state IPC, and all close cycles. The project does **not** claim these hosted pixel checks PASS. The user separately reported physical Windows desktop PASS for minimize/restore, window occlusion, resizing and 150% display scaling, without recording GetDpiForWindow. If either physical regression or native HWND state fails, the M2 gate must be reconsidered.

## 2026-11-21 CI natural EOF fixture and workflow de-duplication

The GitHub-hosted Windows runner has no reliable WASAPI audio output. The earlier short-file EOF test used an AAC-bearing clip, causing `libmpv` to return `MPV_ERROR_AO_INIT_FAILED (-14)`, which the app correctly treated as Error rather than Ended. The diagnostic player log confirmed `playback-restart` followed by `Raw(-14)`. The EOF test now generates a deterministic one-second **video-only** MP4 and continues to require Rust `Ended`; it does not skip natural completion. AAC decoding remains validated independently, and the user separately verified audible output through real Windows speakers.

Both Windows workflows now run on `main` pushes and PRs targeting `main`, with concurrency cancellation for superseded PR updates. Feature-branch pushes no longer redundantly start Windows runners, reducing notifications and preventing older commits from consuming parallel capacity. The SetDPI helper was removed from M2 CI because it could not change the hosted desktop's active DPI; the 150% physical Windows report remains the accepted manual evidence. This change does **not** indicate that M2 has passed CI until the updated checks complete successfully.
