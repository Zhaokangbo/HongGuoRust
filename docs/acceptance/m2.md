# M2 Windows validation

## What has been observed

The user confirmed that the M2-A executable played a local video with picture and audible sound on a real Windows desktop after deploying libmpv-2.dll. The output device model was not specified. The Windows runner separately sampled changing colors in the native child HWND and decoded 48,000 samples of the known AAC tone at 439 Hz. The runner had no WASAPI loopback endpoint.

[Observed M2-A run](https://github.com/Zhaokangbo/HongGuoRust/actions/runs/44758014602) · [Binary provenance](../architecture/m2-player.md) · [Vite audit](m2-npm.md)

## Default client and tests

The Rust service is part of the default Windows build. Every open comes through the native Unicode picker. IPC returns the accepted session ID. Only libmpv's PlaybackRestart can advance Loading to Playing. A single worker owns each successive libmpv handle and drops it before loading the next file. State updates require the corresponding session ID. Closing keeps the HWND alive until the worker joins. Logs distinguish file-loaded, playback-restart, release and worker exit. The pixel test measures screen observation; the GPU presentation timestamp is unavailable.

The M1 smoke launches the release executable, reads the actual UIA text, checks the Rust IPC marker and verifies normal process-tree exit. On the original failing PR runner only the window name was found. The successful Push used the same WebView2 version. The historical failure log lacked a DOM tree, screenshot and backend IPC marker, so its exact cause cannot be reconstructed. A rejected first snapshot used to end frontend polling permanently. The default client retries IPC, and the smoke explicitly requests WebView accessibility, activates the window, waits for the WebView tree and captures failure evidence under diagnostics/.

The M2 smoke exercises the production file picker, replacement, stop, corrupt input, recovery, window geometry on available monitors, minimize/restore, occlusion and twenty launches and closes during playback. Each cycle checks the exit code and its observed descendants. Only scales actually reported by GetDpiForWindow count as real display coverage. Review the CI logs and the PR for observed results. For a missing scale, run the smoke with the relevant Windows display at 100% or 150%.
