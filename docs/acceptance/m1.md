# M1 Windows 原生验收

2026-11-20。M1 验证单窗口启动、Rust 初始快照和关闭后的进程生命周期。实测环境是 GitHub Actions 的 Windows Server 2022 x64 桌面会话。[PR #2 与最新检查](https://github.com/Zhaokangbo/HongGuoRust/pull/2/checks)

| 项目 | 结果 |
| --- | --- |

上述首次原生运行完成了编译和窗口测试，其后一项 Git 跟踪检查发现缺少锁文件，使该次作业整体失败。[原生测试完整日志](https://github.com/Zhaokangbo/HongGuoRust/actions/runs/44748009479/job/136328239652)

## 两个失败点

1. 主分支第一次执行 npm ci 报 EUSAGE，点名缺少 @napi-rs/lzma-linux-x64-gnu@1.5.1。Rollup 将其声明为可选依赖。原离线锁文件省略了包记录，本地 npm 10 构建能通过，runner 的 npm 11 检查整个依赖图时失败。重新生成 package-lock.json，只新增这一项。[主分支失败日志](https://github.com/Zhaokangbo/HongGuoRust/actions/runs/44746719695/job/136323821464)
2. 前端修复后，Git 返回 `pathspec 'src-tauri/Cargo.lock' did not match any file(s) known to git`。从同一次 Windows 运行的 cargo-lock artifact 取回原文件，校验 SHA-256 为 `b953c9e3d9f8441bebe701cc367b23ffec6d7080811c08b0887f2064d8cc5159`，提交至 src-tauri/Cargo.lock。该锁文件包含 Tauri 2.12.7、tauri-build 2.7.6。CI 检查文件已跟踪，再执行 cargo metadata --locked、测试及 release 构建。[锁文件来源](https://github.com/Zhaokangbo/HongGuoRust/actions/runs/44748009479)

## 在 Windows 复测

安装 VS 2022 C++ 桌面开发工具、Windows SDK、rustup、Node LTS 及 WebView2 Runtime。首次安装 CLI 可执行 `cargo install tauri-cli --version 2.11.4 --locked`。CI 使用同版本的官方 Windows x64 二进制并校验 SHA-256。

```powershell
.\scripts\check-windows.ps1
npm ci
npm run build
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo test --manifest-path src-tauri/Cargo.toml --locked
cargo tauri build --no-bundle -- --locked
powershell -NoProfile -STA -File .\scripts\smoke-windows.ps1
```

在 GitHub Actions 的 Windows M1 运行页面下载 HongGuoRust-M1-windows-x64 artifact，可取得这次构建的 EXE，用于在有 WebView2 的 Windows 10/11 工作站复测。桌面实测平台及范围按各次 CI 日志记录。phase1-m1 指向通过 Windows 验收的 main 合并提交。
