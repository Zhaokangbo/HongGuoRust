# M9-B1 — Provider 请求生命周期与错误恢复

基线：M9-A 已通过 Windows 9/9 项实机验收并合入主分支（`886ba5b`）。

## 范围
- 为既有 `catalog_search_page`、`catalog_detail` 增加可选 `requestId`、
  `timeoutMs`，不破坏旧 IPC 调用。新增 `catalog_cancel_request(requestId)`。
- Rust 端约束：请求 ID 不重复；同时活跃请求最多 32 个；
  允许超时 50～30000 ms，默认 8000 ms；请求结束由 RAII 清除注册。
- `ContentProvider` 的带请求上下文调用会在查询之前与之后执行截止时间、
  取消检查；未来执行网络 I/O 的 Provider 应在 I/O 过程中协作检查并设置
  网络层超时，否则无法预empt阻塞系统调用。
- React：每次目录搜索、分页和详情请求都带独立请求 ID 和 AbortSignal，
  超过 8 秒不再等待；取消/离开旧请求不会覆盖新结果。
- 用户可以主动点击“取消请求”或“重试加载”。失败信息转为友好提示，
  不影响已经建立的 libmpv 播放会话。
- 仅使用现有 demo/local 内容源；不新增未经授权的第三方网络接口。

## 重要技术边界
- UI 的 8 秒超时能终止等待、发出取消 IPC；不是任意阻塞系统调用
  的强制终止保证。未来 M9-B2 HTTP Provider 必须设置独立的传输超时，
  并定期检查 `RequestContext`。
- 这些是用户自有的本地媒体与演示内容；不对未授权内容做抓取或播放。
