# M3 playback controls — development acceptance

M3 extends the validated M2 Rust-owned single-libmpv implementation. **The following is a checklist, not a PASS report.**

- Scope: local MP4 and user-supplied direct public HTTPS MP4; no platform sessions, protected content, HLS, account cookies or downloads.
- IPC: open_https, set_paused, seek_to, set_rate, set_volume, get_fullscreen, set_fullscreen.
- Rust libmpv worker reads time-pos/duration every ~250ms; React displays the observed values. A successful seek command is not evidence that a new frame was presented.
- Local media retains the file-only protocol whitelist. Public HTTPS media uses mpv's network demuxing and redirects may be handled by the upstream library; do not paste links to untrusted private services.

## Windows 10/11 real-device acceptance (pending)
1. Use a timecoded local H.264/AAC MP4. Pause/continue: image and sound stop and resume.
2. Seek to 10s/30s and drag slider. Displayed time and rendered frame match within approximately one GOP, allowing decode latency.
3. 0.5× / 1× / 1.5× / 2×. Verify relative wall-clock duration, and check audio for unexpected pitch shifts/discontinuities.
4. Volume 0 / 25 / 50 / 100: verify audible gain on physical speaker or headphones.
5. Fullscreen button and F11; Esc exits. Test resize/restore and 100%/150% Windows scaling.
6. Direct public HTTPS MP4: play, pause, seek, stop, close while loading.
7. Invalid HTTPS URL: command reports validation error without interrupting current playback. Unreachable valid HTTPS URL: Error and then recovery by opening a local MP4.
8. Rapid A→B local and HTTPS switch, natural EOF, 20× close with no surviving processes.
9. Verify no private IPs, credentials or internal API URLs are saved to logs or screenshots.

## Public HTTPS fixture correction — 2026-11-21

The previously suggested Google Cloud Storage fixture (`https://storage.googleapis.com/gtv-videos-bucket/sample/BigBuckBunny.mp4`) returned `AccessDenied` / XML in the user's browser and the player reported libmpv `Raw(-13)` (generic media loading failure). This is not valid evidence that the HTTP player is broken. The application now pre-fills `https://samplelib.com/lib/preview/mp4/sample-20s.mp4` as an alternative public sample. The URL was observed with `video/mp4` content type in external lookup, **but successful playback in the user's Windows environment remains unverified**. Externally hosted fixtures can change or be regionally unavailable.

**Manual verification:** First open the sample URL directly in a browser and confirm it serves or downloads an MP4 rather than XML/HTML; then play the same URL inside HongGuoRust, check picture and (if available) sound, pause/seek, and close while loading. If it fails, capture HTTP status and the application's error. The Rust source URL unit test validates structure only; it makes no network request and cannot establish live availability.
