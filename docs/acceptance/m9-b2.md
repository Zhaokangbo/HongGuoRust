# M9-B2 — 用户自有 JSON 媒体清单 Provider

基于 M9-B1 已验收合并的主分支 `d00a681`。

## 用户输入与存储
- 用户从 Windows 原生文件选择框选择 **.json** 清单；文件只能是
  `schemaVersion: 1`，顶层 `series` 数组，系列包含 `id,title,description?,genre?,episodes`，
  集包含 `id,title,url`。参见 [示例 JSON](../fixtures/owned-manifest.sample.json)。
- 作品 ID 与剧集 ID 仅允许英数字、下划线和短横线，1–64 字节；
  每作品 1–100 集，最多 100 个作品、500 集；清单 ≤256 KiB。
- 标题/说明有长度与控制字符限制，作品 ID 和集 ID 在各自范围内必须唯一。
- URL 经现有 `public_https_url` 校验，只接受形如 `https://public.example.org/movie.mp4`
  的公开 DNS 站点直接 MP4 链接；拒绝 HTTP、localhost、IP 字面量、凭证、非 443 端口和非 MP4 路径。
- 导入前整个清单完成校验。失败不覆盖旧清单；成功使用本机原子替换写入
  `%LOCALAPPDATA%\HongGuoRust\owned-manifest.json`。
- 只复制 JSON 元数据，不复制/上传视频，已导入的原始 JSON 不修改。清空只清除应用缓存的清单。

## Provider 层
- 注册第三个 `manifest` Provider，提供 `manifest:my-test-series` 的独立命名空间。
- 支持与原有 demo/local 在“全部内容源”混合检索和分页。
- 详情与选集只向 UI 返回标题、顺序等元数据，不返回真实 URL。
- 解析单集时才从保存的清单取 URL，再走现有 HTTPS 验证与 libmpv 播放链路。
- 不做远端站点爬取，不存登录信息，不做 DRM、付费墙或鉴权绕过。
  此版使用直接公开 HTTPS MP4，不支持任意 URL、M3U8、远端网站目录接口。
- 仅校验 URL 文本，**不等同于验证 DNS 解析、重定向或媒体的授权状态**；
  新接入更复杂的网络 Provider 时须单独设计网络层防护。
