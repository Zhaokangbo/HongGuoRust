# HG-1 — 红果授权接入架构与待授权入口 Windows 验收

## 状态与基本口径

从 M12-C PR #28 的 `8067f881a12f624413eedd8895b851d1bb05a551` 派生。该 SHA 的 Windows M1/M2 通过，用户报告 M12-C Windows 10/10 实机全部通过。PR #20–#28 仍 Draft/未获合并授权。

HG-1 的新实现包含两种**严格分开的对象**：

- **生产注册**：`HongGuoUnavailableProvider` 是 `hongguo` 名称空间下的**空占位来源**，公开显示「红果接入（待授权）」；`supportsSearch/Detail/Play` 全 false；没有真实剧集、媒体链接、凭据或 HTTP 请求，Rust 内部也拒绝播放。
- **仅模拟测试**：`HongGuoAuthorizedProvider` 与 `ApprovedCatalogTransport` 用合成节目数据单测搜索、详情、排序和精确域名规则。它没有生产注册，没有任何真实红果视频播放，后续取得权利/正式接口后才考虑 HG-2B/HG-3 的网络实现。

- [ ] 3. 从「红果接入」切换回「演示内容」、我的视频、首页及自有清单，现有真实已授权素材/本地内容的搜索、详情、选集和播放均正常。
- [ ] 4. 选择「全部内容源」，demo/local/manifest 仍正常显示；红果占位不会人为增加假内容，也不会干扰分页/关键词搜索和来源 ID。

## 需要保留的安全限制

- 官方微短剧行业方案、云端媒资 OpenAPI、获许可的自有视频可在小程序外播放，与**红果全站任意第三方 Windows 客户端调用**不是同一个许可。
- 合同/API、可访问剧目、版权许可、Windows 媒体播放权、DRM/登录方法没有确定时，禁止接入私有抓取接口或未经批准的播放器令牌。
- 即使未来元数据/账号接口就绪，`HongGuoAuthorizedProvider` 的 Mock 域名检查也不是完整 DNS/IP/重定向 SSRF 防护；HG-2/3 要对真实网络传输单独审查。
- 详细事实依据与需要官方答复的事项见 [HG-1 授权架构调研](../architecture/hg1-hongguo-integration.md)。
