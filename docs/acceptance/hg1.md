# HG-1 Windows 实机验收：红果接入入口与授权隔离

## 当前阶段定义

本阶段**正式开始红果接入工程**，只交付基于现有 ContentProvider 的可扩展入口、能力门控、安全的模拟元数据契约与来源展示。**没有真实红果剧集 API、版权或 Windows 播放授权时，不应出现真实红果作品，也不应该产生媒体请求。** Windows M1/M2 与用户实机验收仍是独立门槛。

开发基线：M12-C PR #28 的 SHA `8067f881a12f624413eedd8895b851d1bb05a551`。该 SHA 的 M1 #44999689761 / M2 #44999689707 CI 全绿，用户已确认 M12-C 10/10 真机验收完成；它们不等于 HG-1 新变更已通过。

## 自动化门槛

- [ ] 同一最终 SHA Windows M1：TypeScript/Node 全量测试、cargo fmt、Rust tests、原生 Tauri build 通过。
- [ ] 同一最终 SHA Windows M2：原生音视频及退出探针通过。
- [ ] Rust 新增 `hongguo.rs`：默认生产 Provider 空列表、三个能力关闭；内部合成数据测试元数据映射、ID/标题长度、剧集数/顺序、非法重复字段、含媒体 URL/临时签名令牌拒绝。
- [ ] `registry.rs`：`hongguo` 独立命名空间可用；`supportsPlay=false` 不止是 UI 标记，任何调用 `catalog_play_episode` 的解析路径都被 Rust 拒绝；不影响 demo/local/manifest。

## Windows 10 项实际验收

- [ ] 1. 打开内容剧库可见「红果接入」入口、切换后 UI 显示「HG-1 / 尚未授权」及明确的无播放权限提示；不出现虚构的红果剧名、宣传封面或热度榜单。
- [ ] 2. 切换「演示内容」→「红果接入」→「我的视频」→「首页」→「演示内容」，没有报错，演示剧集与本地视频仍正常。
- [ ] 3. 「探索内容」的「内容源」下拉项出现「红果接入（待授权）」；切换后结果为空且提示待授权，不会建议搜索演示「城市」「自然」来伪装红果内容。
- [ ] 4. 「全部内容源」搜索与分页仍能看到 demo/local/manifest 原有内容，红果未授权 Provider 不注入假条目，聚合条目总数不凭空增加。
- [ ] 5. 在合法范围内检查程序的网络活动：仅切换红果入口不会发起额外红果媒体、账号登录或未授权第三方请求；不保存 Cookie 或 API 密钥。
- [ ] 6. Rust 单测确认：`hongguo` 的 `supportsSearch/Detail/Play` 均为 false，未授权调用 `catalog_play_episode` 的解析路径返回拒绝，不会启动 libmpv 会话。
- [ ] 7. 内部**合成元数据**契约验证：同名 ID 冲突、嵌入 URL/鉴权参数、过大 payload、错误 schemaVersion 和无效剧集编号均拒绝，不会直接透传到用户界面或播放。
- [ ] 8. 本地自有媒体清单、播放历史、收藏、上/下一集与退出恢复仍按既有 M9–M12 行为，设置文件不因切换红果入口被改写。
- [ ] 9. 反复快速切换来源、输入/清空搜索、取消请求、刷新和切换回首页没有旧请求覆盖、额外后台抓取、卡死或数据丢失。
- [ ] 10. Windows 退出无残留播放进程，M11-A/B/C1/C2 播放与音轨/字幕/预览、M12-A/B/C 诊断与故障恢复均无回归。

## 计划验收后转 HG-2A

- 将当前元数据抽象适配层外接**独立可控的模拟受控服务**，验证合法数据的分页、搜索、详情、失效、取消、连接/读取超时、域名允许列表和 UI 错误回退。
- HG-2A 仍然不依赖真实红果 API，也不能假装播放正版剧集。HG-2B/HG-3 的正式远端数据和 Windows 播放要有具体 API、账号/权限、媒体授权与服务端凭据策略。
- 关键官方依据：`docs/research/hg1-hongguo-access.md`。
