# HG-1 — HongGuo Provider 授权接口边界验收

## 前置状态

本分支从 M12-C PR #28 的 `8067f881a12f624413eedd8895b851d1bb05a551` 派生。M12-C 同 SHA Windows M1/M2 已全绿，用户明确反馈 Windows 10/10 实机验收全部通过；PR #20–#28 仍 Draft/未合并。

**HG-1 不会出现“红果全站”真数据。** 本阶段是授权边界研究和安全 Provider 合约，尚未证明官方红果内容许可或获得任何账号/凭证。

## 目标和实际验证项

- [ ] 1. 同一最新 SHA 的 Windows M1：Rust fmt/tests、Tauri 构建、TS/Node 全量回归通过；Windows M2：原生视频/音频及退出探针通过。
- [ ] 2. `src-tauri/src/catalog/hongguo.rs` 合成 Mock 的搜索、详情、乱序集数排序以及 `MediaTarget::Https` 解析 Rust 测试全部通过。返回的是合成内容，**不是红果剧目**。
- [ ] 3. 非法 ID、重复节目/集数、缺失剧集、恶意/异常上游数据不会产生可播放目标，也不会暴露原始服务端错误。
- [ ] 4. 地址校验拒绝 HTTP、私有 IP、带用户信息的 URL、非约定 CDN 域名、伪装子域名、非 443 端口、非 MP4、fragment；只接受明确允许的域名。
- [ ] 5. Windows 程序原有 `demo`、`local`、`manifest` 来源可以正常浏览/搜索/详情/选集/播放。此阶段**不会**显示未授权的红果真实内容源，不触发红果网络请求。
- [ ] 6. M7–M12-C：收藏历史/断点续播/手动选集/音轨字幕/设置持久化/运行诊断/损坏媒体恢复没有回归。
- [ ] 7. 代码/错误输出和设置文件中不引入 `client_secret`、Cookie、设备签名、账号 Token、带授权 Query 或未审查的第三方请求代码。
- [ ] 8. 对照 `docs/architecture/hg1-hongguo-integration.md` 官方资料，确认已经区分“抖音小程序微短剧商家方案、自有云媒资外部播放能力”与“红果全站剧目获取权”，并记录尚需官方/合作方授权确认的问题。

## 技术边界与后续

本阶段只提供**关闭状态的预备适配器**。它通过 `ContentProvider` 接口与现有 Rust `CatalogService` 解耦，但在正式 `CatalogService::new` 中不注册，不发起任何网络调用，也不存储或上传用户信息。

未来获得许可之后，HG-2 必须单独实现受控 HTTPS transport，明确真实服务端身份、连接/总超时、协作式取消、DNS/IP/重定向策略、凭证只放受信后端、来源与版权标记；不能假定当前的 host 字符串检查已经构成完整 SSRF 防护。HG-3 需进一步确认视频格式和播放授权后才能打开真实剧集。

**验收标准：以上测试均成功并获用户确认，才标记 HG-1 验收完成。官方授权不可用时，不以非官方设备签名/逆向接口冒充合规连接。**
