# M10-C2 — 首页继续观看、已看集数与最近播放联动

## 开发与合并依赖

- 本阶段基于 M10-C1 的最后 CI 成功提交 `8da84c5` 建立 stacked 分支。
- PR #21 临时将 base 指向 `main`，目的是让现有只监听 `pull_request: branches: [main]` 的 M1/M2 CI 运行。GitHub 修改 PR base 不会触发现有默认 `pull_request` 事件类型中的 `synchronize`，因此需要在 base 已设置为 `main` 后提交新变更。
- 由此触发的 CI 验证当前整个 stacked 分支（含 M10-C1），**不代表 C1 的待验收项目自动通过，也不授权直接合并 C2**。
- 在 M10-C1 PR #20 尚未完成剩余 Windows 实机验收并合并前，M10-C2 只允许 Draft PR、独立 CI 和单独真机验收。
- 合并顺序：先完成 M10-C1 全量验收与合并，再重新定位 M10-C2 基线到最新 `main`，重新检查精确 head CI。不得直接把包含 C1 的 C2 分支合入旧 `main`。

## 功能与安全边界

- 首页添加「继续观看」：按最近播放时间合并 M7 本地历史和 M10-C1 已验证的 demo/manifest 进度，最多显示 6 张历史卡片；完整内容仍在「最近播放」页。
- 新 Rust `catalog_recently_watched` 只读取已有历史，逐条重新查询作品/剧集，并验证媒体源指纹。移除、替换或失效的清单不应带出旧书签。IPC 不暴露媒体 URL、查询参数、source fingerprint 或本地文件完整路径。
- 每个 Provider 作品最多在历史列表中出现一条最近观看剧集；不同作品/Provider ID 隔离；不会把 local Provider 再算一次。
- 首页/最近播放卡片支持继续观看/重看；点击时重新拉取作品详情，校验选择的剧集仍然存在，之后调用原生 `catalog_play_episode`。本地项走既有 M7/M8 `library_play`。
- 作品详情页展示真实已观看集数、每集已看完状态或上次位置和进度条；自然 EOF 的最后已看集显示显式「播放下一集」动作。集数严格使用 `Episode.number` 排序，不虚构缺失剧集或自动跨集。
- 「最近播放」页面在原有可检索/排序/清除的本地媒体历史上方增设 Provider 历史，不修改本地历史清除或收藏的写入逻辑。
- 不可用的本地文件显示状态但禁用播放；Provider 源失效不再显示为有效可播放的历史。
- 旧请求返回不能覆盖新的首页状态；局部加载失败保留另一类历史和明确提示。后端限制扫描候选记录及返回数量，不对首页的每张卡单独并发请求。
- 不扩展未授权 Provider，不触碰 DRM/鉴权，公开安装包仍由 Issue #7 阻断。
