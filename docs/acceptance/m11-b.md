# M11-B — 进度条悬停画面预览（独立 libmpv 取帧）

## 开发范围与依赖

- 此分支从 M11-A PR #22 的已通过 CI 提交 `ba4160dfd422d1f1124b42ec7cfb173c189029a9` 派生。PR #20、#21、#22 当前均为 Draft；不得绕过它们尚未完成的合并前置条件。
- 当前实现是独立的 *best-effort* 单帧预览：本地 MP4 是主要验收路径；直接公开 HTTPS MP4 在网络缓慢、未实现 Range、视频没有可检索索引或解码器不支持时，必须安全降级。**CI 编译通过不代表预览 JPEG 必然成功，需要 Windows 实机验证。**
- 不使用主播放器 `seek_to`、不读取其 Mpv 句柄、不输出内容源 URL，也不借助网页视频层偷取原生 HWND 中的画面。

## 技术实现

- 前端根据鼠标相对进度条的横向位置计算时间，5 秒分桶、280ms 去抖后请求 `player_preview_frame(sessionId, seconds)`。浮层始终显示目标位置时间；请求慢或失败时显示清晰退化提示。
- Rust `PlayerService` 在内存中保留**当前 native session 所属 MediaSource**，通过会话 ID + 播放状态验证后将来源交给独立 `PreviewService`；IPC 只返回 `sessionId/timeSec/data:image/jpeg;base64`，绝不向前端公开媒体 URL/本地真实路径。
- 第二个临时 Mpv 实例使用 `vo=image`、`frames=1`、`start` 定位、宽度 320 的缩放、JPEG 质量 60、无音轨、禁用 scripts/ytdl、无硬件解码。远端请求设置网络等待限制；生成时间限额约 2.4 秒，失败只返回 null。
- 一次只运行一个预览解码；新的鼠标目标增加 generation，过期任务在检查点退出。前端也用版本号及 sessionId 二次验证，切集/停止/全屏切换不显示旧图。
- JPEG 先写独立 OS 临时目录，读取并验证后编码为 data URL，退出作用域自动删除。最大单图 384 KiB；LRU 最多 12 张、总约 2 MiB。缓存键包含 native session + 时间桶。
- 预览图来自独立解码源，视觉表现可能与主播放窗口存在轻微帧差；其显示不意味着播放器 Seek、跳集或改变音量。
- 如部分 Windows libmpv 二进制缺失 image VO，前端只显示时间与降级提示，需依据真机证据补齐兼容方案后才标记完成。

## Windows 真机 12 项

- [ ] 1. 播放本地有视频轨的 MP4，在进度条中部悬停，浮层出现该位置的真实帧图片及时间；图片不是主画面的静态快照。
- [ ] 2. 在 0 秒、5 秒、10 秒、靠近视频末尾等位置悬停，缩略图位置大体正确，边界不越界；不需要逐帧精确。
- [ ] 3. 悬停时主画面继续正常播放，声音连续；仅在进度条拖动释放时才真正改变主播放位置。
- [ ] 4. 鼠标在同一 5 秒区间抖动不会明显卡顿，静止 280ms 后能逐步显示预览；快速跨区滑动最终显示最后所在区间。
- [ ] 5. 反复 Hover/Leave、暂停后悬停、快速 Seek、切换全屏，浮层不残留、不覆盖旧内容。
- [ ] 6. 暂停后悬停仍可生成不同位置的缩略图；移动鼠标离开进度条后浮层消失。
- [ ] 7. 播放 Demo/自有 JSON 的 HTTPS MP4，确认可预览则正常显示；如网络源不支持则提示「暂无缩略图」，但不阻断主播放器。
- [ ] 8. 人为断网、低速或坏链接时，预览失败有上限、不会无限加载或引发长时间 UI 冻结，正常播放报错仍由主播放器显示。
- [ ] 9. 快速切换同作品不同集/不同本地 MP4，旧 session 的缩略图不覆盖新 session 的图片，主机没有额外播放窗口和额外音频。
- [ ] 10. 关闭程序后无预览相关持久性大文件泄漏，反复预览不导致缓存长期无限增长或异常进程残留。
- [ ] 11. F11/退出全屏、进度条方向键、M11-A 快捷键、悬停进度条的鼠标拖动 Seek 均正常；帮助浮层不冲突。
- [ ] 12. 抽查 M7/M8 本地断点历史和自动连播、M10-B 上下集、M10-C1/C2 剧集历史/首页续看不受预览影响。
